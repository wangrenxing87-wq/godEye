## 桌面性能样本

18 项原生验收最后一次记录：930 次分片读取，p95 **0.4564 ms**，最大 **2.4702 ms**，客户端报告约 **60 FPS**。该数据来自独立测试世界和桌面显卡环境，包含开发探针开销，衡量的是单个方块读取任务，**不等于整个模组耗时，也不能推导手机帧率**。

方块任务预算是每 tick 最多 2 次、任务间检查 2 ms；一次 C++ 原生调用不能被中断。实体查询、结果聚合、序列化、UI 绘制均有另外的成本。

## 原生验证中修复的问题

- 全空气区域的调色板返回 `None`，不能直接当作未加载或扫描成功；增加完整且分批的回退读取。
- 引擎返回的中文实体名是 UTF-8 字节，统一解码后再组合 UI 文本。
- 换维度清空 UI 节点和注册表，恢复时同时注册和创建界面。
- 世界保存效果与脚本退出回调的先后顺序不固定，保留施加效果时的归属签名，避免写入较短的退出时间签名。
- 原生加载会在就绪握手后补发相同效果事件；仅在恢复后的短时间窗口内接受一次相符的补发，其他替换继续按外部效果处理。

## 凡人等级紫黑背景修复（2026-09-30）

本次直接读取当前游戏窗口，确认 Lv.0 右侧五项背景出现紫黑缺失贴图图案，文字已经为「关」/「未启用」。证据：[修复前实际画面](validation/lv0-background-before.png)。这表明旧实现依赖的 disabled.png 在当前引擎资源中未正常加载；之前的包内文件检查不能替代运行时加载验证。

删除独立 disabled.png 及其全部运行时引用，禁用按钮改为复用画面中已正常加载的 button.png，通过 JSON `grayscale=true` 和 API `SetSpriteGray(True)` 原生置灰；重新可用时恢复原色。默认、悬停、按下三态均同步处理，保留禁止开启、点击即保存及字体位置。

Python 2.7 / Python 3 各 50 项测试通过，两包静态检查均 0 错误。导出包仅 25 个运行文件；包内无 disabled.png 引用，已有贴图引用、CRC、SHA256 与源码一致性均通过，见 [lv0-background-check.json](validation/lv0-background-check.json)。本次原生证据仅确认修复前的问题；未重启当前游戏，修复后的灰色背景仍待重新进入世界确认。
